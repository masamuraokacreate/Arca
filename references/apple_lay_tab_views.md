# タブビュー (Tab views) - Apple Human Interface Guidelines

> 出典: [Apple Developer Documentation - タブビュー (Tab views)](https://developer.apple.com/jp/design/human-interface-guidelines/tab-views/)

タブビュー（Tab View）は、同一の表示領域内で複数の排他的なコンテンツペインを提示し、タブコントロールを使って瞬時に切り替えることができるコンポーネントです。

---

## ベストプラクティス (Best practices)

* **密接に関連するコンテンツ領域の提示に使用する。**
  各タブは、相互に関連する設定項目や、同一ドキュメントの異なる表示モード（例: 「コード」「デザイン」「プレビュー」）などを切り替えるために使用します。
* **ペイン内のコントロールを自己完結させる。**
  あるタブ内のボタンやスイッチが、別のタブのコンテンツに予期せず影響を与えないようにします。各ペインは独立して機能するべきです。
* **明確で説明的なタブタイトルを付ける。**
  各タブの内容を正確に予測できるよう、簡潔な名詞や短い語句を使用します。
* **タブの数は原則として6個以下に抑える。**
  タブが多すぎると横幅が圧迫され、認知負荷が増大します。項目が多い場合は、ポップアップボタンやサイドバー形式のレイアウトを検討してください。
* **タブビューの周囲に適度なインセット（マージン）を設ける。**
  ウインドウの端とタブビューの間に余白を残すことで、ウインドウ全体に属する独立したコントロールとの境界が明確になります。

---

## プラットフォーム別の考慮事項 (Platform considerations)

### macOS
* 設定（環境設定）ウインドウやインスペクタパネルで標準的に使用されます（`NSTabView`）。
* タブバーを上部に表示するスタイルのほか、角丸セグメントスタイルや非表示スタイルも利用可能です。

### iOS / iPadOS
* モバイルアプリでは画面全体の切り替えには「タブバー（Tab Bar: 画面下部）」を使用しますが、画面内の一部を切り替えるセグメントコントロール（`Picker` / `UISegmentedControl`）がタブビューと同様の役割を果たします。
