# ボックス (Boxes) - Apple Human Interface Guidelines

> 出典: [Apple Developer Documentation - ボックス (Boxes)](https://developer.apple.com/jp/design/human-interface-guidelines/boxes/)

ボックス（Box）は、関連するコントロールやコンテンツを論理的なグループにまとめ、明確な視覚的境界線や背景で囲むコンポーネントです。macOSの設定パネル、インスペクタ、ダイアログなどで情報を整理し、視覚的な階層を構造化する際によく利用されます。

---

## ベストプラクティス (Best practices)

* **論理的に関連するコントロールや設定をグループ化する。**
  ボックスを使用することで、互いに関連するコントロールのまとまりを視覚的に明示します。これにより、ユーザは画面全体の構造を素早くスキャンし、目的の設定項目や操作要素を見つけやすくなります。
* **タイトル（ラベル）を付ける場合は簡潔で明確にする。**
  ボックスのタイトルには、グループ全体の目的や内容を表す簡潔な名詞または名詞句を使用します。文末にコロン（`:`）や句点（ピリオド）を付ける必要はありません。また、ボックス内のコントロールからグループの意味が自明である場合は、タイトルを省略してシンプルな境界線のみにすることをおすすめします。
* **ボックスの過度な入れ子（ネスト）を避ける。**
  ボックスの中にさらに別のボックスを配置するような深いネストは、画面を雑然とさせ、視覚的な階層を複雑にしすぎてしまいます。グループ内で項目を細分化したい場合は、ボックスを入れ子にするのではなく、セパレータ（区切り線）、適切な余白（スペース）、あるいはタブビュー（Tab view）や別セクションへの分割を検討してください。
* **適切な境界線スタイルを選択する。**
  アプリの視覚的トーンやmacOSのシステム外観に合わせて、最適なスタイルを選択します:
  * **プライマリ / セカンダリ境界線 (Primary / Secondary border):** 枠線で明確に領域を囲みます。
  * **グルーブ (Groove):** 彫り込みのような立体的な溝で境界を表現します。
  * **カスタム背景 / 塗りつぶし (Custom background / Fill):** 境界線を使わず、背景色やマテリアルで領域を強調します。
  * **境界線なし (No border):** タイトルと余白のみでグループ化を表現します。
* **セパレータ（区切り線）としてボックスを活用する。**
  ボックスは、コントロール同士を水平または垂直に仕切る単一の区切り線（Separator / Divider）としても機能します。

## プラットフォーム別の考慮事項 (Platform considerations)

### macOS
* macOSでは `NSBox` を使用して、グループ化ボックス、タイトル付きボックス、セパレータなどを柔軟に構築できます。
* 設定ウインドウ（Settings）、インスペクタパネル、ドキュメントのプロパティ設定画面などで、関連するコントロール群をカテゴリごとに整理するために標準的に使用されます。

### iOS / iPadOS / visionOS / watchOS / tvOS
* モバイルや空間環境では、従来のmacOSスタイルの外枠線ボックスの代わりに、SwiftUIの `GroupBox`、フォーム（`Form`）、インセットグループ化リスト（Inset Grouped List）、または角丸カード（Card UI）やマテリアル背景を使用してグループ化を行うのが標準的です。

## 仕様とスタイル (Specifications)

| スタイル (Box Type) | 特徴と用途 |
| :--- | :--- |
| **Primary / Secondary** | 標準的な外枠線。設定項目やフォームの主要なグループ化に使用。 |
| **Groove** | 彫り込み線によるクラシックな境界表現。 |
| **Separator** | 単一の水平線または垂直線として、関連項目の間を仕切る用途。 |
| **Custom / Plain** | 背景色や角丸マテリアルを自由にカスタマイズするコンテナ。 |
